# Review, 2 October 2026

One pass over the whole package. I read `BRIEFING-CLAUDE.md`, then the code, and treated `model.ts` and `Navigator.tsx` as the truth. I made code changes only where a person would otherwise miss or misread the ending. Each change is listed in section 6.

## 1. System

**Is it the smallest setup that answers the question?** Mostly, yes. The browser does the arithmetic, and a server function inserts into `bev_sessions`. That is enough. The n8n workflow adds nothing yet, because nothing calls it. The app writes to Postgres itself, through `saveSession`. Leaving the workflow inactive is right. It is a copy of the store step, for the day n8n also runs a schedule.

**What was wrong in the n8n import (now fixed in `n8n/`):**

- `answers` and `claimsOpened` were passed through unfiltered. Any field posted to the webhook would have been stored, including a postcode or a sentence.
- The payload had a different shape from the one `session.ts` stores. Rows from the two paths could not have been counted together.
- `queryReplacement` was a comma-separated string. The JSON payload contains commas, so the insert would have split it into the wrong parameters.
- `crypto.randomUUID()` inside a Code node depends on the sandbox. The id now comes from Postgres (`gen_random_uuid()`).

**Test.** I could not install n8n here: the registry blocked one of its dependencies, from cdn.sheetjs.com. So I tested the next best thing:

- I took the three Code nodes exactly as they sit in the JSON and ran them on a session built from the worked example. I added hostile extras: a postcode, a phone number, a sentence in `claimsOpened`, and a script tag in `uses`.
- I then ran the Postgres node's own SQL, with its three parameters, against `bev_sessions_copy` in a local Postgres 16. The table was created with `like bev_sessions including all` from `0002_bev.sql`.

The result: one row, none of the extras stored, the real table untouched, and an unknown switch key refused. The credential still says `SET_ME`. The workflow is `active: false`.

**What would stop the stored rows from teaching anything:**

1. Rows were not marked with the arithmetic that produced them. Rows now carry `model: "2026-10-02-r2"`, because this pass changed the arithmetic.
2. Touching the worked example made the next row look like a real person. Rows now carry `fromSample`.
3. Nothing tells an interview sitting apart from the team testing, or from a stranger. Before the sittings, add a closed cohort code from the link, such as `?s=i3`. I did not add it, because there are no sittings yet.
4. `withinHorizon` depends on the year frame the person picked. To count "payback inside eight years", use `paybackYears <= 8`, not `withinHorizon`.
5. "Understood — keep this class" (towing) writes `tripFreq: "often"`. A tow car therefore looks like someone who often takes long trips. Count towing from `uses`.
6. A free-text note box stored sentences in a separate table, `bev_notes`. It is removed. See section 6.

**Premature:** the five-node n8n rail. On desktop it sits beside the questions ("n8n · five nodes"). On a phone it is the progress bar. The bar counts five steps while the kicker says "6 of 6". It shows the architecture to a driver. I would hide it for the sittings. I did not change it.

**Still missing:**

- The ElCom year is hard-coded as `"2026"`. ElCom published the 2027 prices on 8 September 2026. On 1 January 2027 the query should move to 2027.
- The postcode is sent to openplzapi.org, a third party, to find the commune. It is not stored here, and the session id is not sent. The page sentence is true, but a careful reader might want to know.

## 2. Decision

**Taps that do not move a number:**

| Tap | What happens |
|---|---|
| "What stings more?" → *each month* / *both* | Only the wording changes. The hint said "the next numbers follow the cost you name". **Changed** to say that only *purchase price* changes a switch. |
| Work: *yes* versus *I can ask* | Same francs. The insight says so. Fine. |
| Used: *only new* versus *no* | Same francs. Fine. |
| Mobile charger, worry chips | Not in the francs, and labelled as such. Fine. |
| **One class down on a small city car** | Moved the wrong number. The class stayed *small*, but 2–8 rental days were added to switching only. It was suggested by default when the barrier was trips. **Changed:** it is off and muted for a small car, like towing. |

**Numbers that move without the person seeing why:**

1. **The year frame changes the title.** In 5 of my 6 test cases, tapping 32 turned "Keep this car" into "The extra price is covered here". In the worked example that meant covered in year 18. For a small petrol car with a trips barrier, in year 26. The row was labelled "How far the picture goes", like a zoom. **Changed:** the row now reads "How long you would keep the next car. The title follows this. The payback year does not." The covered line now reads "Covered in year N, if you keep the next car that long."
2. **"Not sure" kilometres follow the situation label.** A chip on the result, such as *Work appointments*, can change the label, then the kilometres, then the francs. **Changed:** the kilometre line names the label it borrowed, and says the figure moves if the label moves.
3. The *Holidays* and *Longer drives* chips quietly turn One class down on, but only if no switch has been touched yet. Not changed. Watch for it in a sitting.
4. The payback section said "This case falls inside that window [eight years]" whenever the crossing fell inside the chosen frame. At a frame of 12 to 32, that was false. **Changed** to compare with 8.

**The title and the three lines** are clear after the changes:

> Keep this car / CHF 1'605 less a year to run. Fuel or power, insurance, tax and service. / CHF 27'900 more at the start, after selling the car you have. / About 18 years to cover it. This picture stops at 8, the federal study.

Two things were unclear before:

- "after your car is counted in" is now "after selling the car you have".
- "Covered year 5" is now "Covered in year 5".

When running does not cost less, the line used to say "A different purchase will not fix that". That is wrong when One class down is still available, because it lowers the running cost. It now says that a used car only changes the price at the start.

**A second closed question.** One candidate meets both conditions: *how long do you keep a car?* It changes the ending, as shown above, and the path already exists: `keepYears` is on the page, in the payback and in the row. I did not add it. The relabelled row may be enough. Let the sittings decide (section 7).

*"I am not the one who decides"* would move no franc. Its only path is the share note. I did not add it.

## 8. Second workflow (described, not built, not on)

The file worth importing is the Federal Statistical Office's *LIK, Durchschnittspreise für Energie und Treibstoffe, Monatswerte* (XLSX). It is a monthly, official, dated average price for unleaded 95 and diesel. It would replace the pump placeholders 1.79 and 1.93 with a figure the page can date.

The workflow would:

1. Run monthly, a few days after the consumer price index is released.
2. Download the file over HTTP.
3. Read the two national averages.
4. Insert one row into `bev_reference_prices (key, value_chf, period, source_url, fetched_at)`, insert-only.
5. Let the app read the newest dated row and say "BFS, <month>".

Caveats: the BFS asset number changes with each release, so a stable catalogue link is needed. I could not open the current file to confirm its columns.

ElCom needs no workflow, because it is live linked data, but the year has to move each January.
